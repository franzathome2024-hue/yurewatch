# Localisation

YureWatch is bilingual — **Japanese (default)** and **English** — and the whole
interface, including errors, empty states and accessibility names, is translated.
This document explains the design, the terminology policy and how to extend it.

## Why Japanese is the default

The data comes from the Japan Meteorological Agency via P2P地震情報. A reader who
needs an EEW panel most urgently is most likely reading Japanese, and an alert app
must not require someone to find a settings control before they can read a
warning. So:

- the default is **always** `ja`, regardless of the Android system language;
- the switch is visible in the header at all times (`日本語 | English`);
- the choice is persisted and restored before the first paint.

The device locale is **never** consulted — `tests/i18n.test.ts` asserts this with
`navigator.language = 'en-US'`, and `tools/verify-web.mjs` re-checks it in a real
Chromium context created with `locale: 'en-US'`.

## Files

| Path | Role |
| --- | --- |
| `src/i18n/ja.ts` | Japanese catalog. Source of truth for the **key set**. |
| `src/i18n/en.ts` | English catalog, typed `Record<MessageKey, string>`. A missing or misspelled key fails the build. |
| `src/i18n/index.ts` | Runtime: `t()`, `setLocale()`, `getLocaleVersion()`, `onLocaleChange()`, document `lang`/`title` updates. |
| `src/i18n/storage.ts` | Preference persistence: Android `SharedPreferences` bridge → `localStorage` → memory. |
| `tests/i18n.test.ts` | Parity, defaults, persistence, formatting, UI re-render. |

## Rendering model

There is one translation entry point:

```ts
import { t } from '../i18n';

el('span', { text: t('alert.serial', { n: alert.serial }) });
```

- `t()` reads the current locale; there is no locale argument to thread through
  components, and **no `if (locale === 'ja')` in the UI**.
- Panels that memoise their DOM include `getLocaleVersion()` in their cache key,
  so a language switch invalidates them exactly like a data change would.
- `setLocale()` increments the version, writes the preference, updates
  `<html lang>` / `<title>` / `<meta name="description">`, and notifies listeners.
  `main.ts` subscribes with `onLocaleChange(render)` — a switch is one re-render.
- `?lang=en` / `?lang=ja` forces a locale (screenshots, testing). The header
  control remains the normal way to switch.

Values are interpolated with `{name}` placeholders. The parity test asserts that
both catalogs use the *same* placeholders for the same key, so a translation can
never silently drop a number.

## Persistence

| Environment | Store |
| --- | --- |
| Android app | `SharedPreferences` (`yurewatch-prefs`), via the `YureWatchPrefs` JS interface (`NativePrefs.java`) |
| Web / dev | `localStorage`, key `yurewatch.locale` |
| Neither (sandboxed preview, private mode) | in-memory for the session |

`localStorage` is not reliable for the `file:///android_asset/` origin the APK
loads from — it can be cleared with cache and is not guaranteed across process
restarts — so on Android the native store is authoritative and the web store is a
fallback. Only a locale code is ever written; nothing sensitive passes through
that interface.

## Terminology policy

1. **Official vocabulary is translated, never reinterpreted.**

   | Japanese | English | Note |
   | --- | --- | --- |
   | 緊急地震速報（予報） | EEW (Forecast) | never "Warning" |
   | 緊急地震速報（警報） | EEW (Warning) | |
   | 緊急地震速報（続報） | EEW (Update) | |
   | 緊急地震速報（取消） | EEW (Cancelled) | a cancellation does **not** mean there was no shaking |
   | 震度 | seismic intensity | JMA scale, not Modified Mercalli |
   | 震度5弱 / 5強 | 5 lower / 5 upper | compact form `5-` / `5+` in dense UI |
   | 震央 | epicenter | |
   | 深さ | depth | |
   | 津波注意報 / 津波警報 / 大津波警報 | tsunami advisory / warning / major warning | |
   | 主要動 到達 / 未到達 | S-wave arrived / not arrived | |

2. **Intensity numbers keep the JMA scale.** English uses JMA's own rendering
   (5 lower / 5 upper) rather than a foreign scale, so a value read in English
   means exactly the same thing as in Japanese.

3. **Proper nouns stay in Japanese.** Epicentre names (`茨城県南部`), prefecture
   and station names, and JMA area names are displayed as issued. Translating
   them would invent information the source never provided, and would break
   matching against JMA's own area codes.

4. **Hedges are preserved.** "Checking", "not reported", "no tsunami concern from
   this earthquake", "estimated" all survive translation. The English catalog does
   not promise more certainty than the Japanese one.

5. **Times are `Asia/Tokyo` in both languages.** Japanese uses JMA's
   `2026/10/22 16:56:14`; English uses `2026-10-22 16:56:14`. Neither depends on
   the device locale or timezone.

## Adding a language

1. Copy `src/i18n/ja.ts` to `src/i18n/<code>.ts` and translate every value
   (keep the keys and the `{placeholders}` identical).
2. Add the code to `Locale`, `LOCALES` and `CATALOGS` in `src/i18n/index.ts`.
3. Add the language's own name to `lang.<code>` in *every* catalog, and make sure
   the header switch still fits a phone width (see the `.langSwitch` rules and the
   narrow-screen media queries in `src/styles.css`).
4. Run `npm test` — the parity test will list any missing or extra key, any
   placeholder mismatch and any leftover untranslated sentence in the Japanese
   catalog.
5. Re-run `node tools/verify-web.mjs` for the phone-width overflow check.

## What is not localised

- Source data: epicentre/area/station names, and the raw provider name in the
  diagnostics panel.
- Demo payload values (place names inside simulated JMA messages) — they simulate
  real telegrams and must stay shaped like them. Scenario *labels and summaries*
  are localised, because they are app copy.
